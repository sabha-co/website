An app is anything outside Sabha that takes part in your workspace: a CI notifier, a deploy button, an alert feed, an AI bot you run yourself. Each app appears in chat as its own bot user, with a name and an icon. People mention it, message it and click its buttons the way they would with a teammate.

The model is **events out, API in**. Sabha tells an app what happened, over a WebSocket the app opens or a webhook Sabha calls. The app acts by calling the API at `/api/v1` with its key. An app that uses the WebSocket needs no public address, so it can run on a laptop behind a home router.

## Three ways to connect

| You want to | Use |
|---|---|
| Post into one channel from a script, CI or a monitoring tool | An [incoming webhook](/apps/incoming-webhooks/): a URL that only posts, with no key to protect |
| Run an AI bot such as OpenClaw or Hermes | A [known app](/apps/ai-agents/): paste a few commands on the machine it runs on |
| Write your own app that listens, replies and shows buttons | [The apps API](/apps/quickstart/) |

Every app starts with an administrator adding it in **Settings → Apps**. See [Add an app](/apps/add-an-app/).

## What an app can do

- Post, edit and delete its own messages, with files, mentions and [metadata](/apps/messages/#attach-metadata).
- Reply in threads, react, and send [private replies](/apps/messages/#private-replies) only one person sees.
- Show [cards with buttons, menus and date pickers](/apps/cards/) that people use without leaving the channel.
- Declare [slash commands](/apps/commands/) such as `/deploy main`.
- Show a reply [as it's being written](/apps/drafts/), or a line saying what it's doing.
- Read history and search the channels it's in, and look people up to mention them.
- Start direct messages and create channels, if an administrator allows it.

An app is never an administrator. It can't use `@everyone`, and it only reaches channels an administrator put it in, channels and DMs it created, and open channels it joined.

## Reference

These pages explain how the API fits together. Two references come from your own server, with your real URLs filled in:

- **`/skill`** on your workspace (`https://chat.example.com/skill`) is the complete reference as plain text, written to be read by people and by language models. Give it to a coding agent that's writing an app for you.
- **`/api/v1/openapi.json`** is the OpenAPI spec, served without a key. It has every endpoint's parameters and response fields, the [permission](/apps/add-an-app/#permissions) each one needs, which calls are [safe to retry](/apps/reference/#retrying-safely), and the shape of every event.

Where these pages and the spec differ, the spec is right.

If you're moving an app over from Slack, start with [Port a Slack app](/apps/slack/): most of what you send is already in Slack's format.
