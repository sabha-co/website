You can bring your Slack history into a self-hosted Sabha workspace: people, channels, messages, threads and reactions, in one run. The import runs from the command line on your server.

## What you need

- A Slack export ZIP. A workspace owner or admin creates one in Slack under **Settings & administration → Workspace settings → Import/Export Data**: click **Export** and wait for the download link.
- Access to your Sabha server, and the Kamal setup you deployed with. See [Deploy Sabha](/self-hosting/deploy/).

<Aside type="note" title="What your Slack plan exports">
  Free and Pro workspaces export public channels only. Business+ and Enterprise exports also include private channels and direct messages.
</Aside>

## Run the import

<Steps>
  <Step title="Copy the export to your server">
    Put the ZIP in Sabha's storage folder, which the app sees as `/rails/storage`:

    ```bash
    scp slack_export.zip root@your-server:/disk/sabha/
    ```
  </Step>
  <Step title="Check the export">
    This is optional, but it tells you what's inside before anything changes:

    ```bash
    kamal app exec 'bin/rails "slack:validate[/rails/storage/slack_export.zip]"'
    ```
  </Step>
  <Step title="Import it">
    ```bash
    kamal app exec 'bin/rails "slack:import[/rails/storage/slack_export.zip]"'
    ```

    The import checks the export first. To skip that check, set `SKIP_VALIDATION=1`:

    ```bash
    kamal app exec 'env SKIP_VALIDATION=1 bin/rails "slack:import[/rails/storage/slack_export.zip]"'
    ```
  </Step>
  <Step title="Tidy up">
    Delete the ZIP from `/disk/sabha` once you're happy with the result.
  </Step>
</Steps>

## Checking an export

The check makes sure the ZIP opens, that it contains `users.json` and `channels.json`, and that its files can be read. Then it counts what's inside:

```text
Validating Slack export: /rails/storage/slack_export.zip

✓ Valid Slack export

Export contents:
  Users:            25
  Public channels:  10
  Private channels: 0
  Direct messages:  0
  Message files:    47

Warnings:
  ⚠ This export only contains public channels. Private channels and DMs require a Slack Business+ plan to export.

VALIDATION_PASSED
```

An import prints its progress and a summary at the end:

```text

Created 45 threads

IMPORT_COMPLETE
IMPORT_STATS:{"users":23,"rooms":10,"messages":5432,"threads":45,"boosts":234}
```

## What comes across

| In Slack | In Sabha | Notes |
|--------------|-----------------|-------|
| Person | Person | A placeholder account, without email or password. See [People](#people). |
| Public channel | Open room | Everyone currently active in Sabha is added, not only the channel's members. |
| Private channel | Closed room | The people listed in the export are added. |
| Direct message | Direct message | Matched to the original people. |
| Thread | Thread | Linked to its first message. Everyone in the room is added. |
| Reaction | Reaction | Emoji names become emoji. |
| `<@U123>` mention | `@name` | Plain text. See [Message text](#message-text). |
| `<#C123\|name>` | `#name` | Channel reference |
| `<!channel>`, `<!here>`, `<!everyone>` | `@channel`, `@here`, `@everyone` | |

If the workspace has no administrator yet, the import creates a "Slack Import" administrator to own the imported content. It isn't removed afterwards.

## People

Imported people get placeholder accounts. They have no email address or password, so they can't sign in.

Slack bots and deactivated Slack accounts are skipped, along with everything they wrote. The import warns you about the messages it drops.

People can't yet claim their imported account themselves. To connect someone to their history, an administrator sets an email address and password on the placeholder account from the Rails console (`kamal console`).

## Message text

Mentions become the person's first name in lower case, taken from their Slack profile. Display names aren't used.

```text
<@U12345ABC>           → @firstname
<@U12345ABC|display>   → @firstname
<@UNKNOWN>             → @unknown    (if the person isn't in the export)
<!channel>             → @channel
<!here>                → @here
<!everyone>            → @everyone
```

Links keep their text and address:

```text
<https://example.com>              → https://example.com
<https://example.com|Example>      → Example (https://example.com)
```

Channel references keep their name:

```text
<#C12345ABC|general>   → #general
```

Join and leave notices and changes to a channel's purpose or topic are skipped.

## Reactions

Common Slack emoji names become their emoji:

| Slack | Emoji |
|-------|---------|
| thumbsup, +1 | 👍 |
| heart | ❤️ |
| fire | 🔥 |
| tada | 🎉 |
| rocket | 🚀 |
| eyes | 👀 |
| 100 | 💯 |

Any emoji Sabha doesn't recognise becomes 👍.

## Running it again

You can run the same import more than once. Nothing is duplicated:

- People already imported are skipped.
- Rooms are matched by name, ignoring case, and reused.
- Messages, reactions and threads that already exist are skipped.

So if an import fails partway, fix the problem and run it again. A failed run is rolled back entirely, so nothing is left half-imported.

## When something's wrong

| Problem | What happens |
|----------|----------|
| The file isn't a valid ZIP | The check fails and says why |
| `users.json` or `channels.json` is missing | The check fails |
| A file in the export is malformed | That entry is skipped with a warning, and the import continues |
| A Sabha room already has a channel's name | The existing room is reused |

## Limitations

- **Text only.** Files and attachments aren't imported.
- **No profile pictures.** Imported people get default avatars.
- **One-time.** The import doesn't keep Sabha in sync with Slack.
- **Times are kept to the second.**
- **Empty messages are dropped.** A message that's empty once its mentions and links are converted isn't imported.
- **Public channels include everyone.** Every active Sabha member is added to each imported public channel.
- **No claim flow.** Placeholder accounts can only be connected to a real person by an administrator.
